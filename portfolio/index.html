상황

해결

01개발 전 서버 설계 — Docker의 방화벽 우회를 전제로

상황
빈 EC2 한 대, 인프라 1인. Docker가 iptables에 직접 규칙을 넣어 ufw를 우회 → 방화벽 규칙만 믿으면 DB 포트가 인터넷에 노출
해결
  • 포트를 '막는' 대신 '만들지 않는' 설계 — DB·Redis는 포트 매핑 없이 internal 망에만 연결, 모든 요청은 nginx 하나로
  • data 망 이중 보안: 망 격리 + Redis 인증 (팀원 지적 수용)
  • 운영 자동화: 일일 백업 + 복구 리허설 · 5분 감시(상태가 바뀔 때만 알림) · 빌드번호 태그 롤백
  • Prometheus · Grafana 13패널 — 인증 없는 Prometheus는 비노출, 모니터링 망도 internal
성과
외부 공개 포트 22·80·443 3개 · DB 포트는 루프백만 · 롤백 약 4초 · 회수 직전까지 컨테이너 10개 정상

03통신 계층 정리

상황
  • A. TCP는 스트림인데 메시지 경계를 정해두지 않음 — 3개 스레드가 같은 소켓에 send, 앱은 read 1회 → 메시지 뭉침·쪼개짐
  • B. 앱이 SocketClient를 3곳(DataReceiver / AlarmManagerHelper / AlarmReceiver)에서 각각 생성 → 서버가 버려진 소켓을 가리켜 알람 미도달 + connect() 비동기 레이스로 무한 대기
해결
  • A. 구분자 기반 애플리케이션 프로토콜 정의 — 메시지 단위로 조립해 해석
  • B. 앱–서버 연결을 하나로 단일화하고, 알람 등록은 그 연결 위에서 수행하도록 접합면 계약을 정리
성과

의미
