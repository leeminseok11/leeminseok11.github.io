## 증상

서버는 잘 돈다. 앱도 붙는다. 그런데

- 앱 화면에 `PM2.5: 35µg/m³Alarm! PM level: PM2.5: 35µg/m³`처럼 **메시지 두 개가 붙어서** 오거나, 반대로 반 토막이 온다
- 사용자가 등록한 시각에 **알람이 안 온다.** 서버 로그에는 보냈다고 찍힌다
- 가끔 앱이 서버에 붙는 단계에서 **무한 대기**한다

## 원인 A — 메시지 경계를 정하지 않았다

TCP는 **스트림**이다. `send()`를 세 번 했다고 상대가 `recv()` 세 번으로 받는 것이 아니다. 바이트가 순서대로 도착할 뿐, 어디서 끊어 읽을지는 양쪽이 **약속**해야 한다.

서버에서는 `pm_sensor`(5초), `alarm_check`(1초), `handle_client`(응답) 세 스레드가 **같은 소켓**에 `send()`한다. 앱은 `read()` 한 번을 메시지 하나로 간주했다. 타이밍이 겹치면 두 메시지가 한 버퍼에 들어오고(뭉침), 버퍼보다 길면 잘린다(쪼개짐).

<div class="warn">소켓 코드는 틀린 데가 없었다. 틀린 것은 "send 한 번 = 메시지 하나"라는 가정이다. 프로토콜을 문서로 정하지 않으면 양쪽이 각자 다른 가정을 한다.</div>

### 해결 — 구분자 기반 애플리케이션 프로토콜

메시지 끝에 구분자(`\n`)를 붙이기로 **문서로** 정했다. 서버는 모든 `send()`에 구분자를 붙이고, 앱은 바이트를 누적하다가 구분자가 나올 때마다 메시지 하나로 **조립**해서 해석한다.

```
서버 → 앱    "PM2.5: 35µg/m³\n"
             "Alarm! PM level: PM2.5: 35µg/m³\n"
             "Alarm set for Thu Jun  6 07:00:00 2024\n"
앱 → 서버    "set_alarm 2024-06-06 07:00:00\n"
```

뭉쳐 와도 구분자로 나뉘고, 쪼개져 와도 구분자가 올 때까지 기다린다.

## 원인 B — 연결이 셋이었다

알람이 안 오는 문제는 앱 쪽 구조에 있었다. Android 앱이 `SocketClient`를 **세 곳**(`DataReceiver`, `AlarmManagerHelper`, `AlarmReceiver`)에서 각각 생성하고 있었다.

```
앱                                     서버
DataReceiver ──── 소켓 ① ────────▶  clients[0]  ← 5초 데이터는 여기로
AlarmManagerHelper ─ 소켓 ② ─────▶  clients[1]  ← set_alarm 은 여기로 들어옴
                                      alarms[k].client_socket = ②
AlarmReceiver ──── 소켓 ③ ────────▶  clients[2]
```

알람 등록은 소켓 ②로 들어왔으니 서버는 `alarms[k].client_socket = ②`로 기억한다. 그런데 ②를 만든 쪽은 등록만 하고 소켓을 닫거나 버린다. 알람 시각에 서버가 ②로 `send()`하면 **버려진 소켓**이다. 서버 로그에는 "보냈다"고 찍히고 앱에는 아무것도 안 온다.

무한 대기는 `connect()`를 비동기로 띄우고 완료를 기다리지 않은 채 `send()`하는 **레이스**였다. 소켓이 셋이니 레이스도 셋이었다.

### 해결 — 연결 단일화

앱–서버 연결을 **하나**로 단일화했다. 포그라운드 서비스가 소켓 하나를 열어 유지하고, 데이터 수신도 알람 등록도 **그 연결 위에서** 한다. 서버가 기억하는 `client_socket`은 항상 살아 있는 그 하나다. 접합면 계약으로 문서에 적었다: "연결은 하나, 알람 등록은 그 연결 위에서."

## 결과

사용자가 지정한 시각에 알림이 도달하는 **양방향 통신** 완성. 서버 → 앱 5초 실시간 + 알람 push, 앱 → 서버 알람 등록.

<div class="tip">프로토콜을 문서로 먼저 정하는 것이 중요하다. TCP 위에서 "메시지"는 내가 정의하는 것이고, "연결"은 몇 개를 어디서 유지할지 정하는 것까지가 설계다. 둘 다 코드가 아니라 문서에서 시작한다.</div>
