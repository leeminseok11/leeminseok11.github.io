## 처음 계획

캡스톤 설계 초안은 라즈베리파이였다. 리눅스가 돌고, 파이썬이 되고, 네트워크가 바로 붙는다. 센서 값을 읽어 서버 역할까지 한 보드에서 하면 깔끔해 보였다.

## 센서 규격을 읽고 나서

미세먼지 센서로 고른 **GP2Y1010AU0F**(Sharp)의 데이터시트를 읽으면서 계획이 흔들렸다.

- 출력이 **아날로그 전압**이다. 농도에 비례하는 전압을 ADC로 읽어야 한다
- 내부 적외선 LED를 펄스로 켜고, 켠 뒤 **280µs 시점**에 샘플링해야 한다. 펄스 주기 10ms, LED 켜짐 0.32ms

라즈베리파이는 **ADC가 없다.** 외부 ADC 모듈(MCP3008 등)을 SPI로 붙이면 읽을 수는 있다. 하지만 두 번째 조건이 더 문제였다. 리눅스 위의 파이썬에서 280µs 타이밍을 보장하기 어렵다. 스케줄러가 끼어들면 샘플링 시점이 밀리고, 밀린 시점의 전압은 농도와 상관없는 값이다.

<div class="warn">보드를 먼저 고르고 센서를 맞추려 했다. 순서가 반대였다. 센서가 요구하는 것(ADC, 마이크로초 타이밍)을 먼저 적고, 그 제약을 만족하는 보드를 골라야 했다.</div>

## Arduino Uno

Arduino Uno는 10비트 ADC가 내장돼 있고, 운영체제 없이 펌웨어가 직접 돌아 `delayMicroseconds(280)`이 그대로 280µs다. 센서 하나 읽는 데 필요한 조건을 전부 보드 자체가 만족한다.

```cpp
// 데이터시트의 타이밍을 아두이노 코드로 옮기면 이런 모양이다 — LED 켜고 280µs 뒤 샘플링
digitalWrite(LED_PIN, LOW);           // LED ON (active low)
delayMicroseconds(280);
int raw = analogRead(DUST_PIN);       // 10-bit ADC
delayMicroseconds(40);
digitalWrite(LED_PIN, HIGH);          // LED OFF
delayMicroseconds(9680);              // 주기 10ms 맞추기
```

덤으로 얻은 것:

- **비용** — 라즈베리파이 + 외부 ADC보다 싸다
- **개발 편의** — DHT11 온습도, 8방향 LED 바, Text LCD 라이브러리가 전부 있다
- **역할 분리** — 보드는 측정과 표시만, 서버는 PC에서. 서버 쪽을 C로 다시 짤 때 보드를 건드릴 필요가 없었다

## 결과

측정·출력 하드웨어 완성. 농도를 8단계로 LED 바에, 수치는 LCD에. 서버로는 USB 시리얼로 보낸다. 서버 쪽 이야기는 [다음 글](/posts/dust-pthread-server/)에.
